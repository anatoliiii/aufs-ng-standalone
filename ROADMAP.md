# Дорожная карта развития AUFS для Aya OS

## 1. Вектор проекта и целевые эффекты
- **Назначение**: обеспечить воспроизводимую, управляемую и производительную стековую ФС для Aya OS на базе AUFS, сохраняя возможность переключения на overlayfs.
- **Метрики успеха**: соответствие критериям из TESTPLAN.md, положительное решение «go» в AYA-REPORT.md, сокращение трудозатрат на сопровождение за счёт инструментов `auconf` и `unionctl`.
- **Принципы**: минимальная инвазия в апстрим AUFS, документированность всех интерфейсов, непрерывная проверка матрицы ядер/компиляторов.

## 3. Параллельные дорожки
- **Kernel Compatibility**: мониторинг API VFS, бэкпорт патчей, подготовка предупреждений о несовместимостях.
- **Наблюдаемость**: добавление tracepoints/telemetry при необходимости, сбор perf/ftrace-метрик из тестплана.
- **Безопасность**: регулярные проверки LSM/namespace сценариев, ревизия capability-модели в initramfs.

## 4. Управление рисками
1. **Зависимость от out-of-tree патчей** — снижается через автоматическое тестирование на релизных ядрах и кастомных версиях Aya.
2. **Ограничения на количество слоёв** — анализируем лимиты во время E1/E3, документируем рекомендации в `docs/ADMIN.md`.
3. **Перфоманс деградации при copy-up** — A/B сравнение AUFS vs overlayfs в рамках E3, публикация метрик в отчёте.
4. **Недоступность необходимых привилегий в окружениях CI** — эмулирование сценариев через контейнеры с userns, отдельные bare-metal прогоны.

## 5. Следующие шаги после решения «go»
- Подготовка дорожной карты сопровождения (поддержка новых ядер, SLA на обновления AUFS).
- Расширение `unionctl` до полнофункционального управления снапшотами TimeLayer.
- Интеграция с системой телеметрии Aya (журналирование операций AUFS, экспорт метрик).
